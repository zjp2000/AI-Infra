# Kubernetes v1.36：AI 基础设施亮点（精选）

本文仅同步 v1.36 中对 AI 基础设施工程有直接影响的变更，有意过滤了通用发布材料和原始收集数据。

## 筛选范围

- **保留**：影响 GPU/异构资源管理、调度、多租户安全、控制面可扩展性和 AI 工作负载恢复的变更。
- **过滤**：社区参与内容、发布流程叙述以及非 AI 基础设施直接可用的原始爬取产物。

## AI 基础设施高影响力项

### 1) 动态资源分配（DRA）持续扩展

- **优先级列表（稳定版，KEP-4816）**：让工作负载能够跨异构加速器表达有序的回退偏好。
- **扩展资源支持（Beta 版，KEP-5004）**：为 `vendor.com/device` 风格的工作负载提供迁移到 DRA 的路径。
- **可分区设备（Beta 版，KEP-4815）**：支持将单个加速器作为逻辑切片共享。
- **设备污点和容忍度（Beta 版，KEP-5055）**：改善在有问题或预留设备上的安全调度。
- **设备绑定条件（Beta 版，KEP-5007）**：避免在可附加或外部准备的设备实际就绪前绑定 Pod。
- **资源健康状态（Beta 版，KEP-4680）**：在 Pod 状态中直接暴露设备健康信息。
- **ResourceClaim 支持工作负载（Alpha 版，KEP-5729）**：将共享声明语义扩展到 PodGroups 和大型分布式任务。
- **节点可分配资源（Alpha 版，KEP-5517）**：开始探索 DRA 用于 CPU 和内存放置，而不仅限加速器。
- **资源池状态（Alpha 版，KEP-5677）**：增加对池容量和分配状态的即时可见性。

**AI 基础设施影响**：更好的 GPU/NIC 共享效率、更安全的 Day-2 运维、从 Device Plugin 更真实的迁移路径，以及面向标准计算资源的统一放置语义的早期路径。

### 2) 工作负载感知调度方向持续为核心

SIG Scheduling 强调了工作负载感知调度的相关工作（例如拓扑感知调度和工作负载感知抢占讨论）。

**AI 基础设施影响**：更好地适配 gang 式训练任务和异构 GPU 集群中的拓扑感知放置。

### 3) VolumeGroupSnapshot 趋近 GA（KEP-3476）

多个相关卷的组快照/恢复功能，目标是崩溃一致性的恢复点。

**AI 基础设施影响**：改善多卷训练/推理服务的检查点和状态恢复工作流。

### 4) SELinux 重新标记性能（GA，KEP-1710）

基于挂载选项的标记减少了递归重新标记的开销。

**AI 基础设施影响**：帮助减少启用了安全功能的节点上的 Pod 启动延迟方差。

### 5) Mutating Admission Policies GA（KEP-3962）

基于 CEL 的变更策略成为稳定版，减少了对通用策略逻辑的外部变更 Webhook 的依赖。

**AI 基础设施影响**：降低控制面扩展复杂度，减少大规模下的 Webhook 故障模式。

### 6) ServiceAccount 令牌外部签名 GA（KEP-740）

Kube-apiserver 可以将令牌签名委托给外部 KMS/HSM 系统。

**AI 基础设施影响**：为受监管的多集群 AI 平台提供更强的密钥治理。

### 7) 在运营上重要的升级风险项

- **`Service.spec.externalIPs` 在 v1.36 中弃用（KEP-5707）**：在长期移除前规划迁移。
- **`gitRepo` 卷驱动永久禁用（KEP-5040）**：替换为 `initContainer`、镜像构建时打包或 `git-sync`。
- **Ingress NGINX 项目退役（2026-03）**：重新评估 Ingress 维护和安全性。

**AI 基础设施影响**：避免共享平台入口和工作负载启动路径中可避免的升级回退。

### 8) 控制面和升级稳定性信号

- Mixed Version Proxy（Beta 版，KEP-4020）有助于版本偏差升级窗口。
- 控制面可扩展性工作（例如 KEP-5647/5866 方向）持续改善大集群的 list/watch 行为。

**AI 基础设施影响**：滚动升级和大规模运维期间更可靠的稳定性。

## 已过滤的内容

- 社区参与部分和沟通渠道。
- 发布日程/流程叙述（非基础设施决策所需）。
- 原始收集 JSON 和问题板快照（本仓库技术指南未直接使用）。

## 推荐的后续行动

1. 在 staging GPU 集群上验证 DRA 污点/容忍度和分区功能。
2. 审计并迁移所有剩余的 `externalIPs` 和 `gitRepo` 使用。
3. 对低风险策略类试点 Mutating Admission Policies。
4. 使用 VolumeGroupSnapshot 候选者进行检查点恢复演练。
5. 为混合版本控制面窗口添加升级手册。
